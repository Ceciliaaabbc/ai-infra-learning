3. 排序题：模型里的先后顺序

正确顺序是 C → B → E → A → D：

C 查表，把编号变成向量
B 经过 12 个 Block，给每个词补充上下文信息
E 最后做一次 LayerNorm
A lm_head 给每个词打分
D 和正确答案比较，算出 loss

记住一个原则：先加工，再打分，最后对答案。 你把 A（打分）排在了 B（加工）前面。但向量还没经过加工，里面只有每个词自己的信息，这时候打分是猜不准的。

4. 12 个 Block 是干什么的；配置、初始化和优化器在流程里的位置

12 个 Block 是在一层一层地给每个词补充上下文信息。 刚进来时，sat 的向量只代表 “sat 这个词本身”。经过几层之后，它的向量里有了 “是猫坐下了” 的信息。到了最后那个 the 的位置，向量里已经有了 “猫坐在某个东西上”，lm_head 才有可能猜出 mat。

打个比方，就像 12 轮“开会讨论 + 会后思考”，每多一轮，每个人对整件事的理解就更深一点。

你在第 1 题里把配置、初始化、优化器都放进了流程，这三个东西都在，但发生的时间不一样：

配置和初始化：只在造模型的时候做一次，之后每次输入数据都不再重复。
优化器：不属于模型计算的流程，而是在每一步训练的最后才出场。
5. loss 是什么，为什么一开始约等于 10.8

loss 是模型的考试成绩，越小越好。 算法是看模型给正确答案多少概率，然后取负对数：

正确答案是 mat，模型给了它 35% 的概率 → loss = −ln(0.35) ≈ 1.05
模型只给了它 0.01% 的概率 → loss ≈ 9.2，说明错得很离谱

刚初始化的模型什么都不懂，给 5 万个词的概率都差不多，每个词约 1/50257，所以 loss ≈ ln(50257) ≈ 10.8。你在 4090 上第一步的 loss 是 10.95，正好对得上。如果一开始 loss 是 50，说明模型一上来就很自信地给错误的词打了高分，通常是初始化出了问题。

6. 初始化、优化器和反向传播的分工

初始化：你说的是“给 token 计算初始向量”，只说对了一部分。初始化是给模型里所有 1.24 亿个参数填上随机的小数字，不只是 wte 里的 token 向量，还包括注意力、MLP、lm_head 里所有的权重。

一步训练的分工：

前向计算 → 算出 loss → 反向传播 → 优化器更新参数
	做什么	打个比方
反向传播 loss.backward()	算出每个参数应该往哪个方向改、改多少（梯度）	导航：告诉你往哪走
优化器 optimizer.step()	真正动手修改这 1.24 亿个参数	司机：决定实际踩多大油门

反向传播只负责算，不负责改；真正改参数的是优化器。

三、第一套题里的其他补充

除以 √hd 和 LayerNorm 不是一回事（第 6 题）。你的答案“防止数值越来越大或越来越小”，描述的其实是 LayerNorm 的作用。除以 √hd 解决的是另一个问题：两个 64 维向量的点积数值偏大，送进 softmax 后，结果会变得非常极端，接近“一个是 1，其余全是 0”。这时模型几乎学不动。除以 √hd 是把分数拉回正常范围，让 softmax 保持“柔和”。

一句话出的题（第 4 题）：数量 5 道是对的。但模型每次看到的都是从开头到当前位置的全部内容，不是只看前一个词。所以第一道题应该是“看到 The，猜 cat”，而不是“看到 cat，猜 sat”。

为什么用加法就能解决（第 7 题）：反向传播经过加法时，梯度会原封不动地传过去，相当于一条直通的“梯度高速公路”。所以即使网络很深，前面几层也能收到梯度。另外，如果某一层什么都没学到，加上 0 就等于保持原样，不会把已有的信息破坏掉。

推算题（第 8 题）：hd = 768 ÷ 12 = 64。分数矩阵的形状是 (B, nh, T, T) = (4, 12, 1024, 1024)，一共约 5000 万个数。每个数用 fp32 存储占 4 字节，单层就是约 0.2 GB。
